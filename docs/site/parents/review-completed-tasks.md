# Review completed tasks

Child-submitted work appears in **Parents → Home → Pending requests**. This
review step lets a parent keep the agreement clear before points move.

> **For:** Parents<br>
> **Result:** A task is approved, returned for improvement, or closed without
> points

## Review a submission

1. Open **Pending requests** and select the child’s task. The child’s name and
   the type (**Task** or **Reward**) sit on one line.
2. If a comment icon is present, open it to read the child’s optional note. The
   dialog is read-only; it is not a chat. There is no icon when the note is
   empty. The note does not award a photo bonus.
3. If a thumbnail is present, open it only when the photo is needed to review
   the work. It is a task photo kept private to the family.
4. Make one decision:

| Decision | Result |
| --- | --- |
| **Approve** | Awards the displayed task points and the configured photo bonus when a photo was submitted. |
| **Ask to improve** | Returns the task to the child with an optional note. The child can correct it and submit it again; no points move yet. |
| **Reject** | Closes the task without points. An optional note can explain the decision. |

A child can have only one active submission for the same task. The same
catalogue task can be submitted and approved more than once in one local day;
each approved claim still awards its points. **Assign tasks for today** and
**Add completed task** still credit a catalogue task at most once per local
day.

A task photo is resized and stripped of camera metadata before storage;
retention follows the family setting.

## Verify the result

After approval, the child’s balance and **History** show a new task entry. A
returned or rejected task stays visible as a decision record, but does not
change the balance.

If an approved entry was wrong, do not edit the past. Create a transparent
correction with [Adjust points](points-and-corrections.md).
