# Parent dashboard and child cards

Path: **Parents → Home**. This is the everyday control centre. It shows one card for each child, requests waiting for a decision, and a short activity feed.

## The four parent menu areas

| Menu | Use it for |
| --- | --- |
| **Home** | Check balances, give a quick decision, assign today’s work, and respond to requests. |
| **Tasks and rewards** | Build and maintain the shared task, penalty, and reward catalogues. |
| **Settings** | Manage family rules, accounts, devices, services, security, and feedback. |
| **History** | Confirm who received or spent points and when. Entries are a record, not an editable balance sheet. |

## Reading a child card

The large number is the child’s current balance. A positive number means earned points available to spend. A negative number means the child has used part of their allowed credit.

### Credit limit

The **Credit limit** is the lowest balance a child may reach when a parent approves a reward. For example, a credit limit of `-100` lets a child spend down to `-100`; it does not give them 100 extra points.

When half of that credit has been used, KinKudos pauses new reward requests until the balance improves. This keeps the child from requesting rewards while already far below zero. Parents can still review existing requests, and all task actions continue to work.

### Lottery line

If lottery tickets are enabled, the card shows how many tickets the child can still buy in the current Monday–Sunday week. It also warns when one purchased ticket is still unfinished. If it says **Lottery tickets disabled**, either the family-wide switch or that child’s individual switch is off.

## The five quick-action icons

| Icon and action | What it does | When to use it |
| --- | --- | --- |
| ✓ **Completed task** | Immediately awards points for one or more catalogue tasks. | You personally checked the work and do not need the child to submit it first. |
| ⚑ **Assign penalty** | Applies one or more predefined negative point entries, with an optional reason. | Use a clear, previously agreed consequence rather than an ad-hoc deduction. |
| ⇢ **Assign tasks for today** | Sends selected catalogue tasks, and optionally one custom task, to that child until midnight. Completing each task awards its points immediately. | You want to choose today’s tasks instead of waiting for the child to pick them. |
| ± **Adjust points** | Adds or removes any number of points and records the required reason. | Correct an error or make a one-off adjustment that is not a task, reward, or penalty. |
| ▭ **Change credit** | Changes that child’s lowest allowed balance. | Give one child a different spending limit from the family default. |

### Assigned tasks for today

An assigned task is available only on the day it is sent. At midnight, unfinished tasks expire and are visible in parent history but no longer block the child.

You can select **Block reward purchases until these tasks are finished**. This blocks only *new* reward requests from that child. It does not cancel a request that is already pending, and it does not block other actions. You can cancel individual unfinished items or the remaining set from the same card.

## Pending requests

The **Pending requests** section groups requests by child. Each request has a clear decision:

- **Approve** (check mark) accepts the task, reward, proposal, or birthday-date change. Task approval awards the shown points; reward approval deducts the shown cost.
- **Ask to improve** (return arrow) is available for a submitted task. Add an optional explanation; the child can revise and submit it again.
- **Reject** (stop icon) closes the request without awarding points or granting the reward. For rewards and proposals, a reason is required; task comments are optional.

For a task with a photo, select the thumbnail to view it at full size. Photos are private family data and follow the retention setting described in [Parent settings](settings.md).

## History

Use **History** to answer questions such as “Did this reward get approved?” or “Why did the balance change?” Every balance change is a separate, permanent record. If something needs correcting, use **Adjust points** to create a transparent new entry instead of trying to rewrite the past.
