# Release and support policy

KinKudos is a community project maintained on a **best-effort basis**. It is
made for families that run their own instance; it is not a managed hosting
service.

## Which version is supported?

Only the **latest published KinKudos release** is supported. Update to the
latest release before asking for help.

Security fixes are normally released only for the latest version. Older
releases may not receive security fixes, compatibility updates, or support.

## What kind of help is available?

There is no guaranteed response time, service-level agreement (SLA), or
availability commitment. The project is maintained when maintainer time is
available and may be paused or discontinued without notice.

[GitHub Issues](https://github.com/VooZ2/kinkudos/issues) are appropriate for:

- a reproducible KinKudos software bug; or
- a clear feature request.

They are not a general server-administration or hosting support service. In
particular, KinKudos cannot guarantee support for custom Docker, NAS, reverse
proxy, network, VPS, or operating-system configurations.

For installation and maintenance help, first use the [server administration
guide](../deployment-and-maintenance.md) and confirm that your installation is
on the latest release.

## Keep family data private

Never include passwords, API keys, SMTP or storage credentials, databases,
backup files, private family information, photos, or unredacted logs in a
support request or GitHub Issue.

Remove private details before sharing a reproducible error. If the problem
needs information that cannot be safely redacted, do not publish it in a
public issue.

## Reporting a security vulnerability

Do not open a public issue for an unpatched security vulnerability. Follow the
private reporting instructions in the repository's
[security policy](https://github.com/VooZ2/kinkudos/security/policy).
